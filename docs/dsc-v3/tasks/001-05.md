# DSC-V3-001-05: Integrate and verify the machinery milestone

## Lifecycle and purpose

Read the authoritative local documents, `001.md`, and all completed 001 subtask
Outcomes. Update metadata and Outcomes before integration. This is not a place
to postpone unit or conversion tests owned by earlier subtasks; it proves their
combined behavior and resolves integration-only defects.

## Indicative starting files

- Core E2E infrastructure: `tests/e2e/helper_test.go`,
  `test_context_test.go`, and `controller_test.go`.
- Version/GVK and component-count assumptions:
  `tests/e2e/components_test.go` and `resilience_test.go`.
- Fresh installation and legacy upgrade coverage: `tests/e2e/creation_test.go`
  and `v2tov3upgrade_test.go`. The latter must be rewritten or supplemented to
  exercise DSC API storage conversion; its name is not sufficient evidence.
- Recheck both platform samples, CRD patches, and CSV bases named in 001-04,
  plus the init-resource tests, after all generated changes compose.

## Integration checks

1. Review subtask diffs for conflicting scheme, GVK, webhook, generated patch,
   sample, fixture, and test changes.
2. Confirm v2 and v3 generated OpenAPI remain identical and the independent
   baseline/guard fail on an unlisted semantic difference.
3. Confirm production reconciliation uses typed v3 exclusively and the exact
   v2 compatibility allowlist is documented.
4. Confirm v1 has no production code or generated serving, v2 is
   served/deprecated, and v3 is sole storage.
5. Exercise the real `/convert` endpoint in both directions with single and
   multiple fully populated objects, plus a v2 read-update against v3 storage.
6. Verify ODH and RHOAI fresh installs, version-specific admissions, primary v3
   samples, status-subresource conversion, and metadata preservation.
7. Ensure unresolved G1-G7 component shapes are absent. The next data-model
   changes begin only in DSC-V3-006 after accepted contracts.
8. Record the v1-free artifact handoff to future DSC-V3-010. Do not implement
   or run odh-cli qualification in this subtask.
