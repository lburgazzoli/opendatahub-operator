# DSC-V3-006: Implement the accepted v3 API and conversion contract

## Lifecycle and prerequisites

Read `../development.md`, `../decisions.md`, `../PLAN.md`, `../TASKS.md`, and
DSC-V3-005. Update front matter and execution Outcomes before code. Confirm the
v3 machinery from DSC-V3-001 is present and G1-G7 have accepted decisions. If
any mapping is still proposed, block only that part; do not invent behavior.
Use the Modern Go guidance required by `development.md` before every Go edit.
Record new durable decisions before relying on them.

## Objective

Replace the initially identical v3 public API with the fully accepted DSC v3
shape and implement deterministic, lossless v2 <-> v3 conversion, admissions,
generated schemas, and conversion coverage. Component module projections are
owned by DSC-V3-007 through DSC-V3-009.

## Required implementation

### Version-owned public types

- Implement the accepted Dashboard, AI Hub, Data/Feature Store/Data Registry,
  MaaS, Training Operator, and Llama Stack changes in
  `api/datasciencecluster/v3`.
- Keep every unchanged v2 JSON name and semantic unchanged.
- Make each diverging nested public stanza v3-owned. Do not mutate shared
  `api/components/v1alpha1` or internal module types to make both versions
  change together.
- Preserve DEC-011 internal resource names and exclude DCH under DEC-012.
- Keep v2 served/deprecated with version-specific defaulting and validation.

### Transforming conversion

- Extend the v2 spoke's explicit typed `ConvertTo` and `ConvertFrom` methods
  only for differences listed by DSC-V3-005.
- Copy metadata and every unchanged spec/status field exactly. Do not use JSON
  serialization, `unsafe`, cluster calls, defaulting, or validation inside
  conversion.
- Implement populated, absent, empty, deprecated, and conflicting cases exactly
  as accepted. Empty management state remains a wire-level empty value while
  its effective runtime value is `Removed`.
- Preserve every v3-only value through a v2 read-modify-write using the accepted
  explicit field or annotation lifecycle. Remove stale compatibility data at
  the accepted point.

### Admissions and generated artifacts

- Update v3 defaults, validation, warnings, immutability, and update rules for
  the accepted fields; retain compatible v2 admission behavior.
- Update ODH and RHOAI CRDs, conversion patches, samples, API docs, deepcopy
  code, bundles/CSVs, and schema inputs affected by public API changes.
- Maintain v3 as sole storage, v2 as served/deprecated, v1 absent, `/convert`
  registered through v2, and ConversionReview protocol exactly `[v1]`.
- Keep the independent normalized v2 OpenAPI baseline immutable for v3-only
  changes. Update it only when an accepted decision explicitly changes the v2
  wire contract; list those v2 paths separately and add focused v2
  admission/conversion tests. Update the explicit difference inventory without
  allowing v3 generation to overwrite the v2 expectation.

## Tests

For every inventory entry add, in the same change:

- one stable `case_id` in the shared machine-readable registry, with exact
  v2/v3 paths and changed OpenAPI semantics;
- direct v2 -> v3 and v3 -> v2 cases;
- v2 -> v3 -> v2 and v3 -> v2 -> v3 cases;
- populated, absent, empty, and conflict cases;
- status and condition conversion where applicable;
- a v2 read-modify-write preservation case for each v3-only value; and
- version-specific defaulting/validation/warning/update tests.

The shared test runner must record execution of forward, backward,
v2-round-trip, and v3-round-trip categories for every `case_id`; the guard must
fail if any link or executed category is missing.

Exercise real `/convert` ConversionReview requests with single and multiple
objects in both directions. The OpenAPI guard must detect path, type,
requiredness, nullability, default, enum, CEL, and list/map semantic changes and
fail for an unlisted difference.

### E2E implementation

- Add or update an E2E case for every new v3-only representation proving it
  survives a v2 read-modify-write against v3 storage.
- Cover transformed spec, status, condition, absent/empty, conflict, and
  compatibility-annotation behavior included by the accepted matrix.
- Add ODH and RHOAI cases for build-specific defaults or validations.
- The E2E code and fixtures land in this task. Only execution may be handed to
  CI when no suitable cluster is available; record the exact job and expected
  assertions in Outcomes.

## Required gates and definition of done

Run focused API/webhook/envtest suites and:

```bash
make generate manifests api-docs
make fmt
make lint
make unit-test
make build
git diff --check
```

Complete only when all accepted public fields are generated, every difference
has bidirectional direct/round-trip coverage, v2 clients preserve all v3 data,
ODH/RHOAI artifacts agree, and no component-handler behavior was guessed.
