# DSC-V3-009: Implement the Data projection

## Lifecycle and scope

Read `../development.md`, `../decisions.md`, `../PLAN.md`, `../TASKS.md`,
`003.md`, `005.md`, and the `006.md` Outcomes. Update metadata and Outcomes
before code, use Modern Go guidance, and keep GC last. DEC-011 preserves the
internal Data/Feast identity; DEC-012 excludes Data Connection Hub.

## Existing behavior to preserve

`internal/controller/modules/feastoperator/handler.go` currently enables the
existing Feast module from the v2 lifecycle state. Its internal FeastOperator
CR projects derived external-OIDC issuer configuration from GatewayConfig but
does not yet project Feature Store or Data Registry child lifecycle.

## Implementation

1. Consume the accepted v3 `data` children from the typed DSC context and map
   each child independently into the existing internal module contract.
2. Implement the accepted shared-operator enablement and cleanup behavior when
   neither, either, or both children are managed. Empty management state is
   effectively `Removed`.
3. Preserve external-OIDC issuer derivation and its current error behavior.
4. Map each child's readiness, releases, status, and conditions independently,
   including removal and aggregate readiness.
5. Do not add DCH or rename the internal CR, GVK, module, manifest directory,
   or metadata.
6. Keep the accepted v2 Feast/Data Registry compatibility behavior. Do not edit
   public v2/v3 types, conversion methods, the OpenAPI inventory/baseline, or
   central generated DSC artifacts. Route any missing public contract through
   a serialized DSC-V3-006 follow-up applying DEC-003/DEC-007 before resuming.

## Tests

- Table-test the complete two-child state matrix for `Managed`, `Removed`,
  empty, and absent values.
- Assert module enablement, internal CR creation/removal, child projection,
  external OIDC preservation, status, conditions, releases, and idempotence.
- Cover GatewayConfig success and error behavior.
- Add direct and both round-trip v2/v3 conversion cases for every Data field
  affected here, including the accepted fidelity mechanism.
- Add schema-compliance and envtest/status tests and add/update ODH/RHOAI E2E
  cases for independent child lifecycle. Only execution may be handed to CI.

## Required gates and definition of done

Run focused Feast/Data tests and all mandatory Make gates. Complete when both
children behave independently exactly as accepted, existing Feast/OIDC
behavior remains intact, DCH/internal renames are absent, conversions are
lossless, and evidence is recorded.
