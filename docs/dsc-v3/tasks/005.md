# DSC-V3-005: Freeze the consolidated API and conversion matrix

## Lifecycle

Read the local development rules and authoritative documents, update metadata
and Outcomes, and verify DSC-V3-002 through DSC-V3-004 are complete. Do not
start normative consolidation from provisional examples. Record every approved
result in `../decisions.md` before changing PLAN/TASKS. Complete only when the
matrix has no undecided cell.

## Objective

Merge the component-owner contracts with the remaining MaaS and deprecated
field decisions into the single implementation contract for DSC-V3-006 through
DSC-V3-009.

## Inputs already known

- All accepted entries in `../decisions.md` are authoritative. DEC-018 and
  DEC-020 apply only to future Task 010/release work.
- Dashboard input comes from DSC-V3-002; Data from DSC-V3-003; AI Hub from
  DSC-V3-004.
- Current runtime MaaS precedence uses explicit
  `aigateway.modelsAsAService`, otherwise deprecated
  `kserve.modelsAsService`. Conflict conversion is not decided.
- Proposed v3 removes deprecated `trainingoperator` and
  `llamastackoperator`; `ogx` remains. Non-empty v2 behavior is not decided.
- DEC-003 requires both conversion directions, direct tests, both round trips,
  and status/condition coverage. DEC-007 requires a complete normalized
  OpenAPI difference inventory.

## Required matrix

For every changed spec, status, and condition path, record:

| Concern | Required value |
| --- | --- |
| V2 representation | Exact JSON path, type, optionality, default, validation |
| V3 representation | Exact JSON path, type, optionality, default, validation |
| V2 -> v3 | Populated, absent, empty, deprecated, and conflicting behavior |
| V3 -> v2 | Populated, absent, empty, and unrepresentable-value behavior |
| Fidelity | Explicit field or approved annotation lifecycle and precedence |
| Admission | Defaults, validation, warning, immutability, update behavior |
| Tests | Direct both ways, both round trips, status/condition cases |

Include Dashboard core/portal, Model Registry/AI Hub, Feast/Feature Store, Data
Registry, both MaaS fields, Training Operator, Llama Stack Operator, and every
renamed/removed status or condition.

## Remaining owner decisions

- G5: exact precedence for every empty/`Managed`/`Removed` MaaS combination and
  whether conflict warns, rejects, normalizes, or preserves both for v2.
- G6: observable v2 and v3 behavior when v2 supplies non-empty Training
  Operator or Llama Stack Operator state absent from v3.
- Any v3-only value must prefer an explicit v2 compatibility field. If that is
  impossible, approve the annotation key, encoding, conflict precedence,
  cleanup, stale-value behavior, and tests.

## Deliverables and definition of done

- Accepted decisions close G1 through G7.
- `../decisions.md` contains the complete authoritative matrix, or adopts an
  exact repository-local contract file by path and revision. PLAN and TASKS
  contain only consistent summaries and links; they are not normative copies.
- The normalized OpenAPI expected-difference inventory lists every intended
  v2/v3 difference and associates each with named conversion tests.
- DSC-V3-006 through DSC-V3-009 can implement without product judgment.
- Documentation/link checks and `git diff --check` pass; no code is changed.
