# DSC-V3-008: Implement the AI Hub projection

## Lifecycle and scope

Read `../development.md`, `../decisions.md`, `../PLAN.md`, `../TASKS.md`,
`004.md`, `005.md`, and the `006.md` Outcomes. Update metadata and Outcomes
before editing. Use only accepted public names/defaults and Modern Go guidance.
Internal rename work is explicitly excluded by DEC-011.

## Existing behavior to preserve

`internal/controller/modules/modelregistry/handler.go` manages internal GVK
`AIHub`, singleton `default-aihub`, and module/manifest name `modelregistry`.
It projects public `registriesNamespace` to internal `instancesNamespace`,
falls back to the applications namespace when required, and mirrors readiness,
release, namespace, and legacy status. Build-specific v2 defaulting uses
`odh-model-registries` or `rhoai-model-registries`.

- Runtime: `internal/controller/modules/modelregistry/handler.go` and

- Build-specific public-contract audit inputs:
  `api/components/v1alpha1/modelregistry_types.go`,

  behavior is asserted, `tests/e2e/kserve_modelregistry_test.go`.

## Implementation

1. Read the accepted v3 AI Hub fields from the typed DSC v3 context and project
   them into the existing internal AIHub CR without renaming internal resources.
2. Apply only the accepted namespace default/fallback, immutability, update, and
   removal behavior; keep ODH and RHOAI variants distinct where specified.
3. Preserve module lifecycle, applications namespace, gateway domain,
   releases, related objects, and management-state annotations.
4. Map source readiness to the accepted public DSC v3 status and condition
   names. Retain legacy status only where DSC-V3-005 requires it.
5. If an implementation discovery requires a durable behavior not in the
   accepted matrix, stop that portion and add a proposed decision; do not infer.
6. Do not edit public v2/v3 types, conversion methods, the OpenAPI
   inventory/baseline, or central generated DSC artifacts. Route any missing
   public contract through a serialized DSC-V3-006 follow-up applying
   DEC-003/DEC-007 before this task resumes.

## Tests

- Cover `Managed`, `Removed`, empty/absent state and empty, build-defaulted,
  applications-fallback, and custom namespaces for ODH and RHOAI.
- Assert internal CR name/GVK/module name remain unchanged and the projected
  `instancesNamespace`, lifecycle, status, conditions, releases, and related
  objects are correct.
- Cover namespace validation/immutability and v2 compatibility through direct
  and both round-trip conversions.
- Add schema-compliance, envtest/status, idempotence, and removal cases, and
  add/update the ODH/RHOAI cluster E2E cases. Only execution may be handed to
  CI.

when v2 Model Registry and v3 AI Hub inputs produce the accepted equivalent
internal behavior, public names do not leak into internal identity, ODH/RHOAI
behavior is proven, and all evidence is recorded.
