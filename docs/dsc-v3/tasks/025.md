## Actionable follow-up tasks

1. ✅ **DONE — Map Data readiness conditions in both conversion directions.** Map
   `FeastOperatorReady` to `DataReady` in v2-to-v3 and map `DataReady` back to
   `FeastOperatorReady` in v3-to-v2. Exercise both mappings through the actual
   conversion methods, not only the generic mapping helper.
   [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4121761929)

2. ✅ **DONE — Make the MaaS spec-update integration case perform a real v3 update.**
   Change `spec.components.dashboard.standard.managementState`; the top-level
   `dashboard.managementState` path is pruned by the v3 schema and does not
   exercise marker preservation after a spec change.
   [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980881)

3. ✅ **DONE — Make the Platform CRD OLM-owned in both operator bundles.** Add
   the Platform CRD to each CSV's owned APIs for v1alpha1 and v1alpha2, and add
   it to `operators.operatorframework.io/internal-objects`. The OLM bundle
   overlays strip its static conversion and service-CA annotation so OLM
   configures the conversion webhook, matching DSC and DSCI. FeatureTracker and
   TrustyAI ownership/internal-object cleanup is deferred to a separate PR.
   [ODH thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4104188503),
   [RHOAI thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4104188509)

4. ✅ **DONE — Retry envtest CRD conversion updates on resource-version conflicts.**
   Each conflict retry re-fetches the CRD and reapplies the conversion
   configuration. Focused tests cover a conflict followed by success and
   exhausted retries retaining CRD context.
   [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4107289731)

5. ✅ **DONE — Preserve the `TestContext` context in `NewWithT`.** Restore the
   `main` behavior where `NewWithT` uses the context configured on
   `TestContext` instead of implicitly switching to `t.Context()`, which is
   canceled as the test ends. Callers continue to choose the context through
   `testf.WithContext` when constructing the test context.
   [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980919)

6. **Make test-helper deletion semantics explicit.** Treat NotFound as success
   for idempotent `Delete` callers, and provide a strict helper for tests that
   need to assert NotFound; continue propagating other errors.
   [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980910)

7. **Treat empty selector environment variables as unset.** Update `envIsSet`
   so it returns true only when the variable exists and its value is non-empty.
   [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4104188560)

8. ✅ **DONE — Protect the destructive DSC conversion E2E suite.** Require DSCI/DSC
   backup and restore before the suite can delete `default-dsc`; cleanup with
   `deletionPolicy=always` is not a safe substitute when later setup fetches
   that resource.
   [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4107289755)

9. **Move the CRD source-file assertion out of the E2E binary.** Keep
   management-state path transformation assertions in E2E, and put the
   repository-file assertion in a unit test that runs with the source tree.
   [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980931)

10. **Make the optional shell argument array safe with `set -u`.** Guard the
    empty `conversion_webhook_args` expansion in both runner branches while
    preserving all configured arguments.
    [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4107289738)

11. **Allow controller-written conversion-test status to settle.** Increase
    the conversion E2E helper’s default polling timeout from five seconds for
    assertions that depend on asynchronous controller status updates.
    [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4107373351)

12. **Disambiguate versioned API reference anchors.** Give Platform v1alpha2
    and DSC v3 headings and links unique anchors so same-named v2/v3 types link
    to the intended schema.
   [CodeRabbit thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4104188513)

13. **Separate follow-up — Remove FeatureTracker and TrustyAI from CSV-owned and
    internal-object metadata.** The current bundle generator derives ownership
    from bundled CRDs, so this requires a separate scoped change to the bundle's
    CRD contents and CSV metadata.

## Not carried forward

- **Retirement schema propagation wait:** The referenced
  `api/datasciencecluster/v2/retirement_validation_envtest_test.go` no longer
  exists. Retirement validation moved to the v2 webhook, whose integration
  tests cover create and update rejection.
  [Thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980784)
- **V1-free CRD stored-version gate:** The referenced
  `pkg/dsc/compare/openapi_test.go` is absent from this checkout and the
  current DSC delivery path is v2/v3. The old test-specific instruction is
  superseded by the current conversion and retirement coverage.
  [Thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980896)
- **V3 package label and API reference description:** The package label now
  says v3 in `docs/api-overview.md`.
  [Package thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980819),
  [API reference thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4104188524)
- **CSV ownership of DSC v1:** Both CSVs currently list v2 and v3 without a
  v1 owned entry.
  [Thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980827)
- **RHOAI init-resource/sample mismatch:** The annotation and RHOAI sample
  currently match; the existing consistency test covers this contract.
  [Thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980840)
- **Enabled module selection and raw service length:** `EnabledModules()` now
  includes AIPipelines, Ray, and TrustyAI; `RawDeploymentServiceConfig` has
  `MaxLength=8` and the generated API reference shows it.
  [Module thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4104188489),
  [Length thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4104188495)
- **AIHub validation marker placement:** The generated ODH and RHOAI CRDs
  contain the immutability CEL rule under `aiHub`, so the validation is
  attached to the intended schema.
  [Thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4107289709)
- **Explicit Optional marker suggestions:** The referenced fields already use
  `omitempty`, and their generated schemas do not require those fields. Adding
  explicit Optional markers would not change the API contract or fix a current
  admission issue.
  [Data fields](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4121761881),
  [legacy FeastOperator field](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4121761914),
  [v3 Components fields](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4121761942)
- **Resilience excluded-component count:** The suggestion conflates the
  component-controller count with module coverage. The component map is empty;
  AIPipelines and Ray are separately registered in `moduleToControllerMap`.
  The current excluded count matches the 15 v3 `Components` fields and the
  component-map assertion, so changing it to 13 would make that assertion
  inconsistent.
  [Thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4103980942)
- **MonitoringStatus API links:** The current API reference has no
  `MonitoringStatus` section or the reported links to repair.
  [Thread](https://github.com/opendatahub-io/opendatahub-operator/pull/4137#discussion_r4104188530)
- **Duplicate MaaS comment:** The repeated review comment is represented once
  in actionable task 2.
